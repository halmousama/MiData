## Why this is not 1.0 yet

Honest list, in the order it hurts:

1. **There is no application yet.** The workspace, the gate suite and CI now exist, but the only crate
   is `xtask`: no domain types, no store, no engine, no window. Every capability in
   `docs/inventory.md` is still `planned` — by design (product crates are birth-gated, D26), but it
   means there is nothing to install or try.
2. **The gate exists but does not yet guard a product.** `cargo xtask ci` is green on ubuntu and
   windows, and every gate was shown to fail on an intentional violation (P0-1). What it guards today
   is `xtask` itself plus the workspace policy; the layer DAG, file budget, i18n ratchet and scorecard
   become load-bearing as the P0-2…P0-9 crates land.
3. **Legacy parity is transcribed, not proven.** P0-11 extracted 485 oracle cases into
   `docs/oracles/`, but no test cites a scenario id yet, so inventory coverage still reads 0% — the
   parity number arrives with the Phase 0/1 code that passes those scenarios.
4. **The constitution is still over budget.** `AGENTS.md` is 33.5 KB against the amended lean-bootloader
   target of ≤ ~12 KB (P0-10, policy amended by D27) — a context-economy problem that taxes every
   session.
5. **No packaging, no release process in code.** Installers, tags and the release checklist are Phase 7;
   nothing is shippable before then.
